# 夜班工时与工资

班次属于shift_day；计划结束时间不大于开始时间时跨到次日。打卡是带偏移的时间，先存UTC，再用Asia/Shanghai拆分实际日历日。休息区间按夜班日期归属处理，先从实际工作区间扣除。单班最多18小时，打卡须为整分钟。缺IN或OUT整班隔离，不猜补卡。

按实际日历日判断法定假日、周末，法定假日优先3倍、周末2倍、工作日8小时内1倍、超过8小时1.5倍；正常分钟按同员工同日累计，跨班片段共享阈值。参数holidays可传日期列表，默认仅2026-10-01。金额按片段Decimal计算到分，paid为实发工资，差额为应发减实发。此规则用于样例计算，不替代当地劳动法规。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

同一员工/归属日/方向的最高版本若有时刻、时薪、班次、休息或实发金额冲突，则整班隔离；选中IN与OUT的时薪、班次起止与休息起止也必须完全一致。

## 维修单校时

设备打卡机偏差由维修单确认后，可选择两种口径之一，参数为 `correction_policy`：

- `ticket`（默认，推荐）：维修单确认的设备偏差是客观事实，受影响班次内该设备的进出卡全部按偏移修正。申诉只标记异议，不决定是否修正；未申诉员工同样修正，避免“同一批数据一半是错的”。
- `appeals`：只修正申诉员工所在班次，未申诉员工保留原卡，工资维持原样。

打卡 CSV 需含 `device` 列（设备号）；缺少该列时无法按设备定位受影响打卡，维修单不会命中任何班次。维修单字段：`id`、`device`、`offset_minutes`（非零整数，绝对值≤120，正数表示设备慢、需加回）、`window_start`/`window_end`（必须带偏移，按 UTC 存储）、`reason`（依据）、`appeals`（工号列表）。同一批次内维修单号不得重复，窗口不得重叠命中同一张卡。

受影响打卡 = 设备号一致且设备显示时刻落在窗口内。受影响班次 = 含至少一张受影响打卡的 (employee, shift_day)。**班次是修正的最小单位**：同班同设备的进出卡一起修正，不得单边回拨。

以下情形整班不自动修正、转人工（`review`）：

- `WINDOW`：同班同设备存在窗口外的卡，说明维修单窗口未覆盖整班。
- `MIXED`：同班进出卡来自不同设备，单边修正会拆散配对。

校时证据 `times` 按打卡 ID 保存：`original_at`（设备原始时刻）、`used_at`（采用时刻）、`ticket`、`device`、`offset_minutes`、`basis`（维修单号 · 设备 · 偏移 · 窗口）、`reason`、`appealed`、`policy`。段、计算与页面均引用该证据，原始打卡任何情况下都不被覆盖。

校时永远从原始打卡重算，增量不叠加：同一维修单重跑得到同一 `used_at`，重复提交返回 `NOOP`，不增加版本、不二次回拨。

修正版切换在单事务内完成，先校验对账已平且 `archive.sha256` 与自身工资证据一致；任何校验失败或事务异常都回滚，旧版本的正文、版本号与复核状态保持不变。切换成功后版本号 +1、复核状态回到“待复核”，旧版本存入 `run_versions` 供追溯。
